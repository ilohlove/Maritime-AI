# Architectural decisions

1. **Local browser monorepo:** React/Vite and Python/FastAPI are independently testable and portable to a future desktop shell. No container or cloud infrastructure is necessary.
2. **SQLAlchemy + SQLite + Alembic:** a single local file is sufficient for a single officer; explicit versioned migrations prevent implicit schema drift. Production-grade backup/encryption require later work.
3. **UUID records; first profile in UI:** supports multiple records without a premature fleet-management UI. API IDs prevent a singleton table migration later.
4. **Nullable values and decimal boundaries:** unknown is null, not zero or invented content. Dimensions/draft use m, deadweight t, power kW. Three decimal places and bounded magnitude keep values predictable; SQLite native NUMERIC limitations are documented. GT and NT are integer indices.
5. **Per-field JSON provenance:** a small, inspectable mapping prepares extraction without an entity-attribute-value model. PATCH preserves untouched sources and resets changed data to unverified. Current-state metadata is not audit history.
6. **Optional AI contracts and honest mock:** preserve the original disclaimer mock. The online document workflow uses a separate typed provider contract, an optional backend API key, explicit per-request consent and no automatic fallback. No local model is bundled.
7. **Relative API and loopback:** frontend proxy avoids hard-coded remote URLs. Explicit CORS, Origin checking for writes and JSON content types protect the local browser workflow; no claim of local-process isolation or network server security.
8. **Test layers:** Pytest against temporary migrated SQLite proves persistence; Vitest exercises controls/errors; Playwright optionally exercises real services. CI includes Windows and Ubuntu, tests and build. No real vessel fixtures.
9. **System fonts and CSS:** responsive design and simple theme variables avoid UI framework weight and network fonts. English copy has a starting localization boundary, not a full translation subsystem.
10. **No automatic next milestone:** Task 02 depends on review; roadmap entries are intentions only.

11. **Lexical multilingual MVP:** preserve SQLite and use FTS5/BM25 with authorized bilingual query translation instead of embeddings. This adds up to two API calls per question, avoids model downloads and keeps document search local. Translation and lexical recall need evaluation on a maritime benchmark.
12. **Evidence boundary:** the model supplies claim text, excerpt IDs and exact quotes. The application validates membership, rejects model-authored numeric page references/quoted prose and supplies local source metadata. Citation integrity does not prove semantic correctness or guarantee resistance to all prompt injection.
13. **Local originals:** store PDF/text bytes and extracted chunks in SQLite in one transaction. Limit input and extracted size. No file serving, remote uploads, auto-verification or mutation of vessel fields is introduced.

14. **Private owner sessions:** salted scrypt login, opaque random tokens stored as digests in SQLite, absolute expiry and explicit revocation. GitHub Pages uses memory-only bearer transport to avoid third-party cookies; optional same-origin cookies require CSRF. No public signup or tenant isolation.
15. **Conservative AI quota:** atomically reserve two maximum inputs and bounded outputs before inference, never refund uncertain failures. Persistent rate/budget state survives restarts. The single-worker concurrency gate is intentionally not distributed; provider project spend limits remain necessary.
16. **Durable cloud layout:** configurable absolute SQLite and original-document paths, explicit persistence attestation and fail-safe startup checks. New originals are private UUID files; migration preserves existing BLOBs. Operator backup snapshots revoke sessions and preserve quota state.
17. **Preparation only:** production HTTPS/hosts/proxy/origin guards and Pages build configuration are supplied without deploying infrastructure. The manual workflow builds an artifact only. All content on the shared GitHub Pages origin must be trusted; a dedicated custom domain provides a stronger frontend boundary.

18. **Disposable means no paid inference:** an explicitly acknowledged production-secured synthetic test profile may use fresh temporary storage, but cannot present it as durable. Exact bundled fixture-only imports and disabled vessel writes prevent operational-record ingestion. A fixed noncredential API placeholder, guard denial and SDK-adapter denial prevent paid calls even after state loss; a real API test requires normal durable quota storage and separate authorization.
19. **Verified free terms and Pages policy:** provider source examples do not prove current billing eligibility. Render/Koyeb selection remains conditional on official-term verification; current HF Docker creation requires a paid plan and Fly offers a time-limited trial. Pages password/SaaS guidance is an explicit rollout gate; technical build success does not resolve provider policy.
